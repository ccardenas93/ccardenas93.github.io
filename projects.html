Order assistant for a custom-cake bakery

Next.js · OpenAI-compatible API · tool calling · WhatsApp

A chat agent that answers from the bakery's real catalog, suggests cake tiers by number of guests, enforces the 3-day lead time, collects the design photo and logs each order with a code. The owner gets a panel where she sets the price and sends the quote, with the 50% deposit already calculated, to the customer's WhatsApp in one click. The agent never invents prices and hands off to her for delivery, rush orders and complaints. It has rate limits, a daily spending cap and server-side order verification.

Forecasting and hydrology

Hourly temperature forecast for Quito (Iñaquito station)

Python · ECMWF open data · WRF · GitHub Actions · Plotly

An operational forecast that runs every hour with no server: GitHub Actions pulls station observations, ECMWF open data and the national WRF run, applies a model output statistics (MOS) correction fitted per hour of day, and publishes the forecast with an 80% uncertainty band. Every forecast is archived and verified, so the page reports its own skill against raw ECMWF, persistence and the diurnal climatology. Over six months of verification the correction took the mean absolute error from about 2.8 °C (raw ECMWF) to about 1 °C.

Climpact in Python, benchmarked against R

Python · R · NetCDF · climate extremes

Climpact computes the ET-SCI climate-extremes indices used in WMO workshops. I rebuilt its station, gridded and quality-control workflow in Python and compared it with the original R version: all 8.16 million compared values identical, a 24-station batch in 39 s instead of 155 s (12 s without charts), and gridded runs with a tenth of the memory.

National hydrometeorological platform (INAMHI GEOGLOWS)

Angular 17 · Django · PostgreSQL · GeoServer · MapLibre

With Fundación EcoCiencia I maintain and extend Ecuador's public hydrometeorological platform: river forecasts from GEOGLOWS, WRF, satellite precipitation, lightning and soil moisture. My work covers a new Angular frontend, data pipelines that feed the maps, production deployment and performance: the first frame of the map animations went from 6–14 s to about 0.35 s. Wildfire hazard platform for a fire department

Python · Dash · Docker · ERA5 · GIS

Consultancy for a municipal fire department in the Andes. I built a wildfire-occurrence hazard index on a 500 m grid that combines station meteorology, terrain susceptibility and fuel dryness, and validated it against a fire season that was not used to build it. The work ships as a set of Docker services: dashboards of the fire record and weather, meteorological thresholds, and an interactive map where each cell shows how its score was built.
